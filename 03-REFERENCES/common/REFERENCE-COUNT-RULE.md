# Reference Count Rule

Too many equal-weight references create design averaging and generic output.

## Default full-run limit

Each run receives:

- 1 primary visual/composition anchor;
- 1 secondary media/typography anchor;
- 1 motion/interaction anchor.

Default total: **3 visual references**.

A fourth reference is allowed only when it has a non-overlapping specialist role that cannot be covered by the first three.

Common product architecture references (OS23.6, Higgsfield, Figma Weave, existing V2) do not count as visual references because they define product breadth/semantics, not the visual skin.

## Priority

The primary anchor has the strongest influence.

The model must not average references.

If references conflict, resolve in this order:
1. source/product truth;
2. run-specific primary anchor;
3. run-specific secondary anchor;
4. run-specific motion/interaction anchor;
5. common ancestry/reference principles.

## Mandatory evidence

Before coding:
- capture or inspect each assigned reference;
- record exact mechanics/tokens;
- say what will be transferred;
- say what will NOT be transferred.

No new visual reference may be added mid-run without recording why the existing set is insufficient.

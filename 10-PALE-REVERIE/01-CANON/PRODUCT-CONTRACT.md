# PALE REVERIE — Stable Product Contract

This file contains durable product intent. Time-sensitive implementation state belongs in `CURRENT-STATE.md`.

## Product

PALE REVERIE is an original third-person 3D anime action-RPG with surreal dark-fantasy art direction.

The quality reference is the polish/readability of a modern high-end anime action-RPG, not copied characters, UI, lore, maps, assets or proprietary design from another game.

## Visual contract

Target:
- clean dimensional 3D;
- anime cel shading with colored shadows;
- thin colored outlines;
- strong character silhouettes;
- controlled rim light;
- chrome / liquid-silver / pearl / glass materials;
- selective bloom;
- atmospheric depth;
- dreamlike nostalgic cinematography;
- surreal fashion-fantasy composition.

Explicitly not the target:
- paper texture;
- pencil/graphite;
- watercolor;
- canvas grain;
- hatching/halftone as a global render style;
- generic low-poly primitives presented as final hero art.

## Character contract

Eira is the primary visual acceptance asset:
- pale cool porcelain skin;
- large pale-blue half-lidded anime eyes;
- narrow elongated face;
- enormous radial lavender-pink mane as the signature silhouette;
- liquid-silver high-collar suit with central zipper;
- lunar jewelry/amulet;
- Carr, a glossy blue-black crow with amber eye.

Velm and Blu must remain strongly distinct and faithful to their own references.

Reference images outrank convenient generic anime choices.

## World contract

The world should be beautiful, melancholic, strange and coherent.

Recurring motifs:
- black mirror water;
- pearl moon / lunar fracture;
- whale-bone architecture;
- lavender mane-like flora;
- glass sky-whales;
- living Lace;
- submerged lamps and remembered places;
- chrome/transparent impossible structures;
- controlled mint/sage/lavender/silver palettes with selective strong accents.

Surreal elements need a rule or gameplay/world function. Avoid random AI weirdness.

## Thematic contract

Memory is not only lore.

The game should contain concrete situations where memory changes:
- NPC state;
- environment;
- path/access;
- dialogue;
- encounter/reward;
- and/or ending state.

Core question:
what makes a person real — remembered past, present consciousness, or choice?

## Priority order

When scope conflicts, use this order:
1. character/reference fidelity;
2. movement/camera/animation feel;
3. readable combat;
4. dense authored world/art direction;
5. coherent story and honest progression;
6. stability/performance/save integrity;
7. optional side systems.

A smaller strong game is preferable to a larger weak one.

## Verification principle

"Tests green" is not equivalent to "looks right".
"Many triangles/features" is not equivalent to visual quality.
"VLM score" is evidence, not absolute truth.

Visual acceptance uses:
- matched reference/render views;
- multi-angle comparison;
- pairwise old/new review;
- artifact checks;
- founder review for final taste.

## Delivery contract

A successful development stage must be reproducible outside one Browser sandbox.

Important state, source, assets, decisions and evidence belong in Git/artifacts, not only in chat history.

# Copy and IA Protocol

## Product breadth benchmark

Use mature creative platforms such as Higgsfield to verify that Influencer OS does not collapse into:
- one homepage;
- one generator;
- one dashboard;
- a thin prompt wrapper.

The site must explain and expose the real breadth of the product.

## Copy research

Before final public-site copy:
1. inspect current Higgsfield public pages and help/docs;
2. inspect current Figma Weave product/help language;
3. inspect Influencer OS source truth;
4. extract recurring user jobs and vocabulary;
5. write original Influencer OS copy.

Allowed:
- learn category names;
- learn how jobs are decomposed;
- learn sequencing and information hierarchy;
- use ordinary functional labels when they are the clearest terms.

Not allowed:
- copy marketing paragraphs verbatim;
- carry unsupported claims into Influencer OS;
- call a capability LIVE because a reference product has it.

## Copy style target

- concrete;
- product-literate;
- concise;
- visually compatible with editorial design;
- no empty “future of creativity” language;
- no unsupported superlatives;
- no inflated identity-consistency claims;
- always distinguish OS intelligence from external generation models.

## Required copy audit

Every public claim receives one status:
- SOURCE_SUPPORTED
- IMPLEMENTATION_SUPPORTED
- RESEARCH_SUPPORTED
- MARKETING_INTERPRETATION
- REMOVE_UNSUPPORTED
